# Skim reference

Detailed behaviour, configuration, and safety notes. Start with the [README](../README.md); the HTTP contract is in [api.md](api.md).

## Setup

Requires Go 1.26+, Node.js 22+, npm, and Git for ACP verification. Runs on macOS, Linux, and Windows. On Windows, file locking uses `LockFileEx` and agent/Git process trees use Job Objects (killed with Skim); those Windows-specific paths are compiled and reviewed but have not yet been exercised on a Windows machine.

Open Settings and choose **Add provider** to create and name a provider instance, select its protocol/endpoint, and paste its API key. Normal AI setup does not require `.env`, environment-variable names, or a server restart. You can add multiple instances of the same backend and rename them without losing saved keys or role assignments. A fresh installation has no providers or assigned Chat, Review, or Jev models; configure the roles explicitly.

Existing saved providers, keys, and role assignments are preserved. Legacy providers without a display name initially use their existing ID as the name. Optional environment-key references on explicitly configured providers continue to work. [`mise.toml`](../mise.toml) optionally loads `.env` into commands run with [mise](https://mise.jdx.dev); Skim itself does not read `.env`. Export credentials in the launching shell, or use your existing `mise exec -- ./bin/skim` workflow. `.env.example` is the tracked template; never overwrite an existing `.env`. Restart the server after changing its environment. Saved provider keys take precedence over environment keys.

Open **http://127.0.0.1:7437**. The binary embeds the web app built by `make build`; pass `--web-dir /absolute/path/to/web/dist` to serve a different build. Public GitHub PRs can be loaded without a token. Private PRs, writing-style import, and publication require an authenticated token; a fine-grained token needs repository contents read and pull requests read/write as appropriate. Skim uses the authenticated user's own review comments for style—not issue comments or invented examples.

## Reviewing a pull request

1. Start at **Home** to see your review inbox, or paste a `https://github.com/OWNER/REPO/pull/NUMBER` URL. Opening a PR lands on **Guide**. Configure providers/models in Settings before using automatic analysis. **Opening a PR automatically sends PR metadata with available file evidence to the review text-model provider (recommended review units), each complete file's metadata and patch to the Jev provider when one is configured (per-file risk and test-only scope), and each flagged file's patch to the review text-model provider again (the factors behind its rating).** This can include private code. No model response is required before the diff becomes usable; merely listing the inbox calls no model.
2. Open the cog in the top bar to configure named providers and models on the separate Settings page; **Review** returns to your workspace. Chat and Review require an OpenAI-compatible text backend; the optional Jev role requires a TypeSafe backend. Leaving Jev unset turns risk labels and test-only collapsing off entirely. Setup guidance is expandable; missing configuration does not block the filesystem tree.
3. Tabs are ordered **Guide**, **Diff**, **Description**, **Commits**. Choose **Guide** for the recommended unit navigator, unit summaries, and associated diffs, or **Diff** for the filesystem jump list and continuous changes. While review units are being prepared, Guide shows a status panel (with a shortcut to Diff) instead of reshuffling files under you; if units are unavailable it explains why, offers Retry or Settings, and lists files in folder order. Unit links jump to explanations; file links jump to code without leaving Guide. Both tabs share comments, selected ranges, reviewed marks, and mounted editors. The navigator and chat panel can be resized or collapsed, and mobile exposes a Units section. **Unified / Side by side** controls diff layout independently. Diff code is syntax highlighted in GitHub's colors (see `web/README.md`). **Collapse tests by default** is an optional saved browser preference, initially off. It collapses only complete changesets Jev identifies as test-only with at least 95% confidence and 95% test-only probability; uncertain or unclassified files remain open, regardless of filename. Turning it on also folds previously opened tests, except active selections and comment/reply editors. Restored file URLs respect collapsing; explicitly opening a file or jumping to code still reveals it. It never marks files reviewed. Panel sizes and diff layout remain session-only. Unsent edits survive tab changes and collapse.
4. Use **+** beside a diff line to create a **Pending** human comment. Agent review and actionable check findings create **Suggested** comments with **Approve / Edit / Deny** actions. Approve moves a suggestion to Pending; pending comments have Edit/Delete. **Insert code suggestion** prefills the selected new-side lines, lets you edit the replacement or delete them, and previews a GitHub-compatible suggestion block. Approving does not apply code. **Finish Review** lists pending comments with Approve/Comment/Needs changes outcomes; only explicitly pending comments are published.
5. Select line numbers and use **Ask agent** to dispatch an ACP check. After acceptance the question box clears and you can keep reading, use chat, switch PRs, or start more checks. Each thread runs in a separate worktree; only simultaneous follow-ups in the same thread are blocked. **Activity** groups checks by status (Needs permission, In progress, Failed, Cancelled, Complete) with cancellation and nonmodal permission requests tied to their exact job/PR. **Clear finished** hides completed, failed and cancelled checks from Activity; their threads and reports stay in Verify. Open a thread for the full report and its actionable suggestions. Ctrl/Cmd+Enter submits the focused composer. Browser reload discards unsent input, not accepted jobs or saved review work.

**Verify** starts with a compact list of checks. Open one conversation at a time, then use **Back to checks** to switch; unsent follow-ups stay with their thread. Status and relevant permission actions remain visible, while checkout paths, IDs, and timestamps live under **Details**. New checks start from selected code rather than a second “New check” button. Range highlighting is continuous; individual selected line numbers no longer get blue boxes, while keyboard focus stays visible.

**Reviewed progress:** each file has a Reviewed checkbox, shared by both views. Checking it saves the mark and collapses the file; unchecking expands it. A unit checkbox marks/unmarks all its files in one update, shows a mixed state when only some are reviewed, and collapses a completed unit to a header. Clicking file links or expand controls reopens reviewed content without clearing its marks; restoring a file URL does not force expansion. This is local reading progress, not a GitHub review submission or an AI verdict. Marks survive PR switching and restarts. Reload retains unchanged complete diffs, but changed/renamed/removed files become unreviewed; unavailable/truncated files also reset when base/head changes.

**Agent review:** **Agent review** checks out the PR head (with the base commit available) and has your ACP agent review the whole change, reading surrounding code and running focused checks it asks permission for. It ends its report with comments as JSON; each must anchor to one hunk of GitHub's diff, and comments that don't are listed in Review comments as could not be anchored, with the reason, instead of being dropped silently. Valid ones become Suggested comments in one save when the agent finishes; the full report stays under **Agent report** in Review comments. Progress shows the phase (preparing checkout, reviewing, saving) and points to Activity when the agent is waiting for permission. Runs are limited to 30 minutes, need an ACP agent in Settings, and stop if the page that started them disconnects. ACP checks have independent queued/preparing/running/summarizing/terminal states, not a global busy lock. Detailed check output is saved in the thread; the configured Review model extracts concise, evidence-supported findings, or none. If extraction fails or the model is unconfigured, the report remains with an explicit suggestions error. Publication/checkout cleanup waits for an active review or checks on that PR; other PR checks do not block it.

**Approve without comments:** open **Finish Review**, choose **Approve**, and submit. Neither a pending comment nor a summary is required. The overview and submission identify the exact PR/base/head, and stale pending comments are explicit blockers.

Code suggestions use [GitHub's suggested-change review format](https://docs.github.com/en/pull-requests/how-tos/review-pull-requests/reviewing-proposed-changes-in-a-pull-request): a fenced `suggestion` block inside the comment body. Replacement whitespace is preserved, including multiline code, embedded backticks, and empty deletion. Current RIGHT-side complete ranges support insertion; stale, old-side, or missing/truncated code explains why insertion is unavailable. Ordinary prose comments remain possible. Applying the published suggestion to a branch happens in GitHub, not automatically in Skim.

**Saved comment migration:** old manual drafts and approved comments become Pending; unapproved AI drafts become Suggested. Previously denied comments are removed. Delete erases comment content and retains only an ID/revision tombstone so a delayed response cannot resurrect it. Published comments remain immutable locally.

**Existing discussions:** GitHub inline threads load independently of AI analysis and appear on their current diff lines. Older, missing-root, and out-of-range threads remain separate; **GitHub** in the review panel lists all of them. Replies post directly to GitHub, not to Pending. They need a token with suitable access. Refresh errors retain previous threads; uncertain delivery retains the composed text and requires checking the thread before explicitly retrying.

## Review inbox, description, and commits

Home lists open GitHub PRs requested for review from you or assigned to you, using the authenticated token user's login by default. Requested and Assigned labels retain both reasons when a PR appears in both searches. GitHub's `review-requested` search includes requests to your teams; it excludes completed review requests, while an assignment alone does not prove a review remains outstanding. Optional username and `OWNER/REPO` filters change the search, not your authentication identity.

The inbox needs a GitHub token: one saved in Settings, or else the variable named by `githubTokenEnv` (normally `GITHUB_TOKEN`). Missing credentials, inaccessible repositories, rate limits, and network failures produce actionable errors without blocking manual public PR URL loading. Search pages are combined and ordered by most recently updated; GitHub caps each requested/assigned search at 1,000 results. Incomplete results show warnings—narrow the repository filter or inspect GitHub rather than assuming everything is listed. Searches reflect visible indexed repositories, are not atomic snapshots, and global REST searches cover at most 4,000 matching repositories.

Opening a row uses the normal PR loader; Home alone neither switches your active PR nor loads all those diffs or starts AI analysis. The review workspace offers **Description**, **Commits**, **Diff**, and **Guide**. Description shows the full supplied PR body. Commits loads lazily for the exact PR/base/head, showing complete commit messages, author/date, and safe links to GitHub. A moving PR requires reload; GitHub's 250-commit PR API limit is explicitly reported alongside the total. Diff and Guide review the same complete PR comparison: existing inline comments, selected ranges, publication, and verification do not become per-commit reviews.

PR views have shareable URLs such as `/github/OWNER/REPO/pull/123/diff?file=src%2Fmain.go` and `/github/OWNER/REPO/pull/123/guide?file=src%2Fmain.go`. The old Files route is replaced by Diff. Browser refresh reloads the current PR from GitHub before fetching discussions, preserving the tab and selected file instead of returning Home. Back/Forward works between all four tabs and the inbox. If GitHub reports changed base/head refs while loading comments, use **Reload pull request** beside the error; current refs are fetched again, while saved comments on older code remain stale rather than being moved.

**Description** opens with a review-guide card: "Classified into N review units", the unit titles in reading order (each jumps into Guide), and **Start guide**; while units are prepared it says so, and if they fail it offers Retry or Settings. The author's description follows unchanged. Skim no longer generates a PR-wide AI overview: the author's description states intent, and the unit summaries explain the shape. Diff and Guide keep a collapsible author description above the code. In **Guide**, a separate persistent unit navigator shows completion and the current unit; unit explanations stay beside their associated files while scrolling. The unit rail and filesystem tree keep separate width/collapse choices. Both reader tabs retain the same mounted file editors, including when reviewed units are collapsed or Guide is still preparing. The configured Review model supplies units and risk factors; Jev and manual Reviewed marks remain independent.

## Configuration

**Saved API keys and GitHub token:** state lives in the OS user-config directory plus `skim` (`~/Library/Application Support/skim` on macOS; `$XDG_CONFIG_HOME/skim` or `~/.config/skim` on Linux). `--data-dir` or `SKIM_DATA_DIR` selects a different directory. Existing state is not moved. Keys and the GitHub token persist across restarts in the same directory, as plain text protected by file permissions (`0600` file, `0700` directory), not encryption or an OS keychain; protect backups.

Paste a key or GitHub token and choose **Save settings** to save or replace it. A blank password field keeps the saved value; **Remove saved key**/**Remove saved token** stages explicit removal until Save settings, and **Keep saved key**/**Keep saved token** cancels that removal. Inputs clear after a successful save. Saved values take precedence over environment-variable references (a provider's `apiKeyEnv`, or `githubTokenEnv`). After removal, an available environment value becomes active and is shown as coming from the environment; clear the reference too if you want no fallback. ACP authentication stays with the agent.

Provider URLs include their API prefix. `openai` providers use `/chat/completions`; `typesafe` providers use the real `/systemone` typed-question protocol. HTTPS is required except for loopback model servers, and redirects are refused. A provider with neither a saved key nor an `apiKeyEnv` reference sends no authorization header, useful for local model servers. Saved keys are bound to the provider ID, protocol, and endpoint: changing the endpoint/protocol requires explicitly replacing or removing that key in the same save. Settings and keys commit together; failed validation or a pre-rename persistence failure leaves the working pair and running analysis unchanged.

Provider presets are optional form conveniences, never implicit saved configurations. Anthropic or another gateway uses the existing OpenAI-compatible `/chat/completions` protocol, **not** a native Messages adapter; provider display names never select a special adapter. Review and recommended grouping request [strict structured outputs](https://developers.openai.com/api/docs/guides/structured-outputs) using `response_format: {type:"json_schema", json_schema:{name, strict:true, schema}}` with separate concrete `review_comments` and `review_groups` schemas. Every object has required fields and `additionalProperties:false`. The selected endpoint/model must support this format; provider errors remain visible without fallback or automatic retry. Chat and style import omit `response_format`. Semantic checks still reject invalid paths, incomplete groups, and invalid diff anchors.

All roles initially are empty. Configured chat/review roles require an OpenAI-compatible text provider, and the Jev role requires a TypeSafe provider. Jev is **not** a renamed chat model and cannot generate prose. Deleting all providers and clearing their roles remains empty across restarts. Display names are trimmed, nonblank, and at most 100 Unicode characters; stable provider IDs bind roles and saved keys.

The **review** role also automatically plans logical review units when a PR loads. Saving a changed analysis provider/model/key restarts the affected analysis and can send that PR's evidence to the newly selected provider. Empty roles disable their model calls with visible configuration errors; they do not produce simulated risk or recommendations. Renaming providers and ACP/chat-only settings changes leave completed analysis intact. Cosmetic names are excluded from cache identity, including previously saved successful analysis. Saving keys does not discard saved comments or unsent review inputs.

Startup environment variables are listed in the [README](../README.md#configuration). GitHub-token and agent environment defaults initialize a new state directory only; saved Settings take precedence thereafter. Command-line `--listen`, `--data-dir`, `--web-dir`, and `--dev-origin` override their runtime defaults. The former `SKIM_OPENAI_BASE_URL`, `SKIM_CHAT_MODEL`, `SKIM_REVIEW_MODEL`, `TYPESAFE_BASE_URL`, and `TYPESAFE_DEFAULT_MODEL` startup variables no longer create providers or model assignments: create a named provider and select its endpoint/models in Settings instead. Already-saved configurations are unchanged; merely exporting `OPENAI_API_KEY` or `TYPESAFE_API_KEY` does not create a provider.

## ACP setup and model selection

Install an agent that implements [ACP v1 over stdio](https://agentclientprotocol.com/protocol/v1/initialization), and authenticate it using that agent's own supported login workflow before starting Skim. Set its executable and each argument separately in Settings; no shell command interpolation occurs. **Select the ACP model using that agent's documented model flag in `args` or its persistent configuration.** Skim does not invent a universal model flag or send unsupported session model/config methods. Thus chat, review, Jev, and the ACP agent's model are independently configurable, but ACP model names/options depend on the installed agent.

Settings includes presets for these installed adapters; presets only fill executable/arguments and never install, authenticate, or run an agent automatically:

| Preset | Install outside Skim | Command / arguments |
| --- | --- | --- |
| [Claude Code](https://github.com/agentclientprotocol/claude-agent-acp) | `npm install -g @agentclientprotocol/claude-agent-acp` | `claude-agent-acp`, `[]` |
| [Pi](https://github.com/svkozak/pi-acp) | `npm install -g @earendil-works/pi-coding-agent pi-acp` | `pi-acp`, `[]` |

Pi requires Node.js 22+ and Pi 0.81.0+. Complete `pi-acp --terminal-login` outside Skim and configure Pi's model/providers separately. Pi uses its own local filesystem/tools, not delegated Skim filesystem/terminal capabilities; do not assume a `/model` slash command or automatic permission approval. Claude Code authentication/model setup likewise belongs to its adapter/agent. Keep a custom command configuration for other ACP agents or documented model arguments.

Skim prepares an isolated checkout automatically **only when you request selected-line verification**. Set `acp.managedRoot` in Settings to an absolute parent folder, or keep the default `<private data directory>/workspaces`. The parent can be empty or contain unrelated files: Skim creates its own unique, journaled namespace and never adopts another checkout. Legacy saved `workingDirectory` and `SKIM_ACP_WORKSPACE` are no longer used. Migration selects the new private default and leaves your former checkout untouched; select an intended parent folder explicitly if desired.

The provider supplies the canonical GitHub HTTPS repository and `refs/pull/NUMBER/head` (including fork PRs). Skim fetches the inspected head/base into an owned shared bare cache, then gives each verification thread a distinct detached worktree. Concurrent agents never share a working directory or process journal. Follow-ups in that thread reuse its clean matching checkout. A changed head/root never overwrites existing changes. LEFT selections use the fetched base commit for old content while the checkout remains at HEAD. Model-only review/chat and PR loading need no checkout.

Successful GitHub publication (`COMMENT`, `APPROVE`, or `REQUEST_CHANGES`), including reconciliation of uncertain delivery, ends the local review round and removes all its clean managed worktrees. **Remove checkout** performs cleanup without publishing. Saved threads, reports, and comments remain; later verification recreates its checkout. Changing views, switching PRs, or disconnecting does not cancel an accepted check or clean a worktree.

Dirty worktrees are preserved with cleanup errors so changes can be rescued. Explicit discard confirms the current checkout set; adding, replacing, or removing a checkout invalidates old confirmation. Cleanup failure never turns successful publication into a failure or resubmits it. Failed/uncertain publication retains checkouts. Cleanup waits for active review/checks on that PR; independent chat, remote replies, and checks on other PRs do not own those checkouts.

Crash safety: before an agent can start, the journal durably records that the checkout is being verified; the agent's process group is recorded right after it starts and before any protocol message, and a failure to record it kills and drains the agent. Normal completion clears the record only after the group has drained. After a crash, Prepare, Finish and discard refuse to reuse or delete the checkout while the recorded group can still execute (the process table is only queried; Skim never kills a recorded PID, so a reused PID can only cause a refusal). Once the group has stopped, reuse and cleanup resume. If the process was never recorded, Skim cannot prove the agent stopped and keeps the checkout: stop any agent, then remove both the checkout folder and its Git registration yourself (for example `git worktree remove` in the owned cache); on retry Skim retires only the owned empty record, never deleting files on your say-so. A present folder or a live recorded group is never bypassed, and confirmed discard does not bypass this. A missing agent command is refused before any clone, cache or checkout is created.

The private ownership journal and per-namespace markers must agree with canonical paths and Git repository/head identity before reuse/removal. Unsafe symlinks, replacements, and unmanaged paths are refused rather than claimed. Changes to the configured root do not forget old ownership. Git fetch credentials use the configured GitHub token (saved, or from its environment variable) through an ephemeral credential helper; tokens are not stored in remotes/configuration or command arguments. Inherited Git overrides and system/global Git configuration, hooks, and templates are disabled for managed Git operations; there is no submodule/dependency installation or PR test execution during preparation. Git failures report bounded, credential-redacted diagnostics.

**Cache versus checkout:** finishing removes worktree contents and Git registrations, not the shared bare cache or ownership markers. Those remain for subsequent reviews and safe restart recovery and can contain private repository objects. Protect the managed root and data directory. No automatic operation mutates or deletes user-owned checkouts.

Skim starts each job's executable, negotiates ACP protocol 1, creates a session, prompts it, collects actual assistant text, and handles explicit permissions in Activity or the thread without a modal. It advertises no client filesystem/terminal capabilities; agents may use their own tools. Follow-up history is supplied to a fresh session. Cancellation/timeout sends `session/cancel`, cancels only that job's pending permissions, and drains the process group after a grace period. Jobs retain a five-minute bound. Accepted work survives HTTP disconnect and PR navigation; shutdown cancels/drains jobs, and startup reports interruptions rather than silently rerunning commands.

**This is not a sandbox.** Agents run as your OS user with your environment; malicious agents or PRs can be dangerous. Review permission details and use an isolated environment for untrusted code. Agents may execute their own tools without requesting client permission. Do not put secrets in command arguments. Agent stderr/RPC error payloads are not echoed because they can contain credentials. Read the full thread report's commands/results/limitations before approving extracted findings; neither an agent report nor a suggested code change is proof of correctness.

## Persistence and publication safety

The data directory is private (`0700`, state file `0600`). One process owns it. State—including plain-text saved provider API keys outside the public Settings object—is committed by synced temporary file, atomic rename, and directory sync. Settings and their keys are a single transaction; errors are surfaced. A failure after rename reports durability uncertainty but cannot leave mismatched settings and keys. Each repository/PR keeps its own comments, groups and conversations, so switching PRs or restarting does not erase work. PR text, private diffs, chats, drafts and saved API keys **are** persisted locally; protect this file and backups. No encryption or OS keychain is used.

Loading validates metadata against the complete paginated file snapshot, including a final base/head check; a moving PR causes an explicit reload error, never a mixed-commit snapshot. Changed base/head invalidates unpublished anchors and conversations while retaining them visibly as stale. GitHub head is checked again immediately before publication and verification. GitHub still owns the final atomicity of review creation; Skim binds the request to the inspected commit SHA.

Risk and recommended units are persisted independently with the exact PR evidence signature and relevant model configuration. Risk also includes a versioned judgment policy: an upgraded risk rubric invalidates old badges on the next load/settings save, without rerunning completed grouping or discarding review work. Documentation-only changes do not bump that policy. Same-snapshot, same-policy reloads reuse successful results without paid calls; changed evidence or analysis configuration invalidates only the affected results. Interrupted risk resumes remaining files on reload. Failed attempts remain visible until explicit refresh or a relevant configuration/policy change. PR switches, refreshes, and shutdown cancel obsolete work; exact snapshot/run identities reject late completions. Analysis polling never replaces comments, chats, style, settings, selections, or unsaved editor text.

Before publication, a local journal records a unique hidden `skim-review` marker. After success, pending comments become Published and cannot be resent or edited locally. An ambiguous response or crash is reconciled against the authenticated user's submitted GitHub reviews on the recorded head before another send. If delivery cannot be established, Skim refuses to resend; retry reconciliation and inspect GitHub instead. Do not remove an uncertain review's hidden marker. Definitive rejections clear the journal and preserve pending comments.

Recovery limitation: an ambiguous request that never reached GitHub cannot be proven absent by the API. Skim conservatively keeps publication and comment edits blocked for that PR if reconciliation never finds it. There is no automatic retry/resend or force-clear action. Other PRs remain usable; do not manually discard the journal unless you have independently resolved the remote state and accepted the duplication risk.

## Evidence and model limitations

- GitHub's files API has a 3,000-file ceiling; larger PRs fail explicitly. Binary/omitted/truncated patches are labeled. Anchoring and automatic draft review require complete patches. Missing-patch risk remains **unassessed**, never implicitly low; every changed path still appears in navigation and must be included in the model's units.
- When configured, Jev makes one typed **change-impact** decision from each complete file's metadata and patch, not the PR title/body, other files' risk, or reading priority. Risk means the potential impact if the change is wrong, not whether it contains a bug. Low covers explanatory prose and localized changes with limited failure impact; medium covers bounded behavior/integration changes; high requires a concrete path from changed behavior or actionable instructions to serious security, data-integrity, availability, or compatibility consequences. A new narrative documentation page is normally low, even when discussing production, security, or concurrency. Destructive runbooks and operative configuration, policies, scripts, or schemas can still be high regardless of path/format. File size, newness, and missing tests alone do not establish high risk.
- Skim flags a file only when Jev is confident: **high** needs at least 80% probability on high, **medium** needs at least 80% on medium-or-high combined; anything less is shown as low (no badge). The displayed confidence is that supporting probability. It is not the probability of a defect and is not independently calibrated by Skim.
- After review units are saved (so it never delays the guide), the review text model receives each flagged file's patch and its level definition and returns up to three **factors worth checking**, each anchored to changed lines in one hunk. Anchors are validated against the patch; out-of-patch lines, markup, or more than three factors reject that file's factors and show the error, never dropping the level. An empty answer is shown as "nothing in this diff supports the rating". Each flagged file shows its level, confidence, the level's meaning, linked factors, and a reminder that unflagged files still need review. Risk progress counts every file plus every flagged file. Successful results are saved immediately; a failure on another file does not erase them. Per-file evidence can miss dependencies outside the supplied patch.
- The same Jev request also classifies **test-only changes**, independently of risk. Changed test code embedded in a production file can qualify; mixed runtime changes, shared operational configuration, documentation about tests, and incomplete patches do not get a filename-based exemption. Only high-confidence positive assessments enable default collapsing. Scores are advisory rather than guarantees, and manual expansion/selection remains authoritative. Older risk-only caches refresh automatically without clearing reviewed marks or completed reading units.
- The review text model sees all available PR evidence together and plans related units in natural reading order: foundations/interfaces before consumers where supported, with relevant implementation/tests/callers together rather than risk sorting or a separate bucket for tests. Each unit gets a one-or-two-sentence summary, keeping the response short so the guide arrives sooner; there is no PR-wide introduction. The text client's whole-response limit remains 8 MiB, and provider context/output limits still apply. Invalid prose, extra fields, or unknown, omitted, or repeated paths reject the whole guide; there is no fabricated fallback. Group descriptions are generated context, not review findings or proof of executed verification.
- Jev evidence is capped at 96 KB per judgment. Grouping uses the text client's existing 4 MiB serialized-request bound and the selected provider's context limits, not Jev's smaller evidence cap. No evidence is silently truncated. Risk and grouping failures are independent and visible; unavailable recommendations never block tree navigation. Background persistence failures stop analysis with a visible error; an error that cannot be written to disk remains visible only in the running process.
- Agent review sees the whole checkout, not only the patch, but its comments can only anchor to files whose GitHub patch is complete; incomplete files can still be discussed in the report. It is an agent's judgment, not static analysis or proof that unmentioned code is safe. Chat includes available PR evidence and fails visibly if request/provider context limits are exceeded. Generated anchors are validated against the actual diff.
- Style import searches bounded recent review-comment history in the selected repository, filtered to your authenticated user. No samples is a visible error; it does not pretend to infer your style from others.
- Loading automatically sends PR evidence to the Jev and review text-model providers. Explicit review, chat, style import, and ACP verification can send additional evidence to their configured providers/agents. Model outputs and Jev decisions remain untrusted; AI suggestions must be approved into Pending before Finish Review can publish them alongside human pending comments.

## Desktop app

The version comes from `info.productVersion` in `cmd/skim-desktop/wails.json`; the icon source is `cmd/skim-desktop/build/appicon.svg` (render it to `appicon.png`, from which Wails generates the `.icns`/`.ico`). Linux needs GTK 3 and WebKitGTK 4.1 (Debian 13, Ubuntu 24.04 or newer); the `.deb` declares them and installs the `skim-desktop` command and a menu entry.

**macOS signing:** `make package-macos` signs the app and DMG (hardened runtime, secure timestamp, bundle ID `sh.mackie.skim`) when `MACOS_SIGNING_IDENTITY` names a Developer ID Application certificate in your keychain (use its SHA-1 hash from `security find-identity -v -p codesigning` if several share a name), and notarizes and staples both when `NOTARY_PROFILE` (a `notarytool store-credentials` profile) or `NOTARY_APPLE_ID` + `NOTARY_PASSWORD` (app-specific password) + `NOTARY_TEAM_ID` is set. Without them it builds an unsigned DMG, which Gatekeeper blocks until it is opened with right-click → **Open** (or `xattr -dr com.apple.quarantine Skim.app`). Notarization failures are reported but not fatal unless `NOTARY_STRICT=1`.

**Releases:** pushing a `v*` tag runs `.github/workflows/release.yml`, which builds the DMG on macOS, signs and notarizes it with the repository secrets `MACOS_CERTIFICATE` (base64 `.p12`), `MACOS_CERTIFICATE_PASSWORD`, `MACOS_SIGNING_IDENTITY`, `NOTARY_APPLE_ID`, `NOTARY_PASSWORD` and `NOTARY_TEAM_ID`, and attaches it with `SHA256SUMS.txt` to a GitHub Release. Bump `info.productVersion` before tagging. Running the workflow manually exercises signing and notarization without publishing. Windows and Linux packages remain local builds and unsigned (SmartScreen warns).

Desktop behaviour:

- The window loads the service from the loopback address (`SKIM_LISTEN`, default `127.0.0.1:7437`) with the same Host/Origin protections as a browser. If the port or data directory is in use (for example `./bin/skim` is running), the window explains the failure instead of starting; quit the other instance or give one a different `SKIM_LISTEN` and `SKIM_DATA_DIR`. Opening the app again focuses the existing window.
- Started from Finder, the Dock, or a Linux desktop launcher (no `TERM`), Skim imports your login shell's environment (`$SHELL -l -i`), so `GITHUB_TOKEN`, provider key variables, and the `PATH` that finds `git` and ACP agents work as they do from a terminal. Variables the launcher already set win, except `PATH`. Windows apps already receive the user environment. `SKIM_WEB_DIR` is ignored: the desktop app always uses its embedded web app.
- `target="_blank"` links (GitHub, Markdown links) open in your default browser. On macOS, the standard Edit menu enables copy/paste shortcuts and **View → Reload** (Cmd+R) reloads the page.
- Quitting cancels and drains running analysis and ACP checks, as stopping `./bin/skim` does.

## Development

The Vite proxy must target `http://127.0.0.1:7437` with `changeOrigin: true`; Skim accepts only its bound loopback Host and the exact configured development Origin. There is no wildcard CORS. Rebinding/foreign Host, cross-site requests, cross-origin mutations and non-JSON mutations are rejected. Requests are bounded to 1 MiB. Do not expose either server on a public interface or put it behind an untrusted proxy.

`make check` builds the web app, then runs Go tests and frontend type/Svelte checks (the `web`, `internal/host`, and `cmd/...` packages embed `web/dist`, so it must exist before they compile). `make build` builds the web app and the `skim` binary that embeds it; the [desktop targets](../README.md#building) build the Wails app. Backend protocol fixtures are test-only and do not supply runtime data. See [the HTTP contract](api.md) for endpoint/resource details.
